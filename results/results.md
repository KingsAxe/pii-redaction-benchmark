## Definitions and limits

- Matching ranks positive-overlap pairs by overlap size, then earlier ground-truth start, earlier prediction start, lower ground-truth index, and lower prediction index. Label correctness and exactness are checked only after one-to-one assignment; neither is prioritised. Equal-span competing labels can be resolved by prediction order.
- After assignment, strict means same mapped type and exact span; overlap means same mapped type and nonzero overlap. A matcher miss is an entity left unmatched after assignment, even if predicted characters cover it. Unmatched mapped predictions differ from strict/overlap false positives, which equal prediction count minus the corresponding true positives. ID precision is per-class precision under that full assignment. A zero score with no ID predictions is the scorer's convention.
- Leak, exposure, and character over-redaction use the union of all mapped prediction spans, independently of assignment or label correctness. Raw labels are retained; unmapped labels do not count as redaction, following the Phase 2 scorer.
- Decoy-hit predictions inspect only unmatched mapped predictions and count the first overlapping decoy per prediction. Predictions matched to PII can also cover decoy characters without appearing in this count. ORDER_ID decoys hit by ID instead counts distinct decoy annotations touched by any mapped ID span. These are different counting measures; neither substitutes for character-level over-redaction, the share of non-PII characters covered by the mapped prediction union.
- IDs assigned PHONE are the matcher's ID-to-PHONE assignments. An entity is fully uncovered when no mapped predicted characters cover it; partly uncovered means at least one but not all characters exposed.
- Timing records analysis calls only, after five preliminary unrecorded dev warm-up calls. Main median/p95 use all stored test timings and the Phase 2 percentile helper. The unchanged scorer additionally drops the first five stored timings; its original latency output is retained in evaluation_details.json and the explicitly named scorer columns in results.csv. p95 is the 95th percentile, calculated with the scorer's linear interpolation; it does not remove outliers. Neither timing calculation changed.
- custom_generic is archived experiment 01; custom is experiment 02. The generator never emits BVN/NIN IDs starting with 0, which benefits custom's nonzero-leading rule. Bare random order IDs remain ambiguous. This is synthetic, template-based, small-scale evaluation with one spaCy model.
- The generator-dependent leading-zero exclusion improved ID precision on this dataset. Both custom variants have equal reported character leakage and over-redaction rates. Equal aggregate rates do not establish identical covered character positions.
- Baseline predictions for spacy, default, and ng_phone were generated on dev/test before freeze (dd6b474). After the two-source freeze (853bcbb), all five test configurations were regenerated and committed (da55731). Phase 4 and this reporting patch rescore those archived predictions without inference. Test error records were first generated after freeze; prediction generation and rescoring are distinct operations.
- Latencies are single sequential runs on this machine and may reflect cache, host load, and run order; they do not establish a universal speed ranking.
- Full scorer outputs, denominators, source hashes, and prediction hashes are in evaluation_details.json. All error records with snippets are in error_analysis.md.
