## Decisions

- Phase 1-2 files and benchmark evidence remain unchanged. Earlier phases did not push; the user's final publication instruction explicitly authorizes this task's Git fetch/push to KingsAxe/pii-redaction-benchmark and overrides the earlier push restriction for this task.
- The Phase 6 instruction separately authorizes feature-branch creation/push and a draft PR, not merge or implementation. Preserve frozen benchmark evidence and historical manifests; new demo dependencies and observations will be isolated under demo/ only in a later authorized task.
- Default spaCy pipeline stays enabled; NG phone recognition is additive.
- Before freeze, test predictions may be structurally validated, but no test error analysis is viewed.
- Compatibility assumption: use doc_id exactly when present; otherwise use the exact legacy file value as ID. Ground truth is not rewritten. The user was asked about this choice; no answer received before implementation proceeded with this documented assumption.
- Baseline outputs use spacy, presidio_default, and presidio_ng_phone config names.
- Presidio email validation uses tldextract's bundled suffix snapshot, without network or machine-dependent cache. The initial default run attempted a suffix download and fell back; artifacts were regenerated with explicit offline handling before this commit.
- Stage B reports both strict and overlap ID recall and overall micro precision from the unchanged scorer.
- Stage B selected the highest observed strict dev ID recall, breaking ties with overall strict micro precision. This comparison rule was applied after the three experiments; it was not preregistered.
- Nonzero-leading ID candidates reduce phone-shaped matches on this synthetic dev set. This is a dataset-specific assumption, not a universal rule for real identifiers. Cued-only matching was rejected for its recall loss.
- The generator's gen_11digit() never emits IDs starting with zero; the accepted review addendum makes this dependency explicit.
- Freeze schema: configs.custom and configs.custom_generic each hold source and sha256; runner selects the corresponding source and checks its digest before any custom test processing.
- Reported median/p95 use all stored post-warm-up test timings with the Phase 2 percentile helper. The scorer's extra-first-five-drop latency is preserved separately in the CSV and JSON; no scorer code or predictions are altered to work around it.
- Phase 4 adapts exact document-ID prediction keys to Phase 2 file keys in memory. Matching, label mapping, leak, precision, recall, and decoy definitions remain the Phase 2 implementation.
- Error analysis contains every scorer miss and decoy-hit prediction, with additional type-confusion, partial-match, and character-exposure records. Categories can overlap; they must not be summed as unique entity counts.
- Test latencies are single sequential machine runs; cache and host-load effects prevent universal speed-ranking claims.
- Decoy-hit predictions and distinct ORDER_ID decoys hit by ID predictions have different units and scopes; neither substitutes for character-level over-redaction. Equal reported custom-variant leakage and over-redaction rates do not establish identical covered character positions.
- Source snapshots, experiment timestamps, hashes, raw dev predictions, and full dev metrics are archived under results/tuning/. The standard custom dev file matches the selected archived run; restoring it did not trigger a new experiment.
- This file is updated in every commit. Each entry describes its containing commit by subject; its hash is recorded in the next commit to avoid self-referential hashes.
